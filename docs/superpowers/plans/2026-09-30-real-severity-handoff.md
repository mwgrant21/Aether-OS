## What shipped (behaviour)
Severity values:
- failed = 4, and killed = exactly 2, which is set last. The Ledger shows killed as a label with no failure styling.
- A stall is 4, flagged exactly once. Stall lines appear on the roster only, never in Comms.
- "Recovered." appears only when the stalled dispatch later completes. A stall followed by a silent outcome clears the stall line.
- Slowness is capped at 2 (SLOW_FACTOR 3). The tool-error floor is 3 at >= 3 errors in the subagent file, on completed dispatches only.

Usage and storage:
- Usage that was never reported is stored as NULL and shown as a dash, never 0. That holds on the collector, the live path and the Ledger.
- Schema is v9, rebuilt by table rebuild in both Node and Go.
- The collector median only counts dispatches that finished earlier (`ended_at_ms <`), with window 20 and minimum 5.
- The live baseline persists to `~/.aether-os/duration-baseline.json`. It tolerates a BOM, never throws on a bad file, logs one diag line per error code, and flushes within a 500 ms bound on quit.

Stall timing:
- Measured from the subagent file's last write.
- A future mtime is accepted up to 5 min ahead, clamped to now; beyond that it is ignored.
- If there is no link to a subagent file, it is measured from dispatch start.
- Nested dispatches are recorded, but they are never swept for stalls.

Live path:
- Completions are handled at both tick sites.
- tick() calls are serialized.
- A generation counter makes a pty respawn in the middle of a tick write nothing.
- Comms gets exactly one line per final narration. The narration payload carries `subagentType` and `final`.

Core and collector copy:
- The core lives in `electron/severity/`.
- The collector copy is GENERATED by `scripts/sync-severity-core.mjs`, and a parity test checks it.
- **Do not hand-edit `collector/src/severity/`.** After a regeneration on a CRLF checkout, `git status` can show a copy as modified with an empty diff. `git checkout -- <file>` clears it.

## Rulings made during execution (decisions taken on the user's behalf)
Each ruling below reads: what was decided, why, and what it costs if wrong. The full ledger (37 rulings, 10 user decisions) is on work-it at `.superpowers/sdd/2026-09-30-real-severity/progress.md`. The load-bearing ones:
- **Tasks ran sequentially on one branch instead of in parallel worktrees.** Only wall-clock time.
- **The parser anchors status and usage by POSITION.** This overrode the plan's strip-then-match approach, because a quoted `</result>` could inject usage. If a future notification format puts status after the summary, it scores 1, which is the safe direction.
- **Unwrapped truncated text keeps positional behaviour.** Real notifications arrive wrapped.
- **The collector median is time-bounded.** It overrides the plan's SQL, because a backfill was scoring history against the future.
- **"Recovered." only when the post-stall status is completed.**
- **The Ledger shows dashes for missing usage.** This is in scope because Task 10 labelled exactly those rows, and it matches the CLAUDE.md null-not-0 rule.
- **Comms completions only for final narrations, resolved through `subagentType` on the payload.**
- **tick() is serialized.** It fixes double handling and the shared-offset race.
- **Nested dispatches are recorded but never swept.** About 94% of them complete by `tool_result`, and sweeping them would mark them fatal.
- **The future-mtime tolerance is 5 min, clamped.** Ignoring every future mtime turned the most active dispatches fatal.
- **F15:** stall is measured from dispatch start when there is no subagent link. A long healthy run with no link can show a stall line until it completes.
- **The Go ingest issue is not filed.** Filing is outward-facing and is left to the user.
- **The minor-fix rounds were capped, then extended.** At the user's request, every deferred minor was taken anyway.
