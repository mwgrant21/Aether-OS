# Visible communication U2 checkpoint

U2 provider supervision is implemented on `feat/visible-communication-u1`, following `bf57a36`. No bridge, UI, or live model turn is activated by this checkpoint.

## Implemented

- Windows provider processes start suspended and enter a Job Object before resuming. Descendants inherit membership. The supervisor terminates the job and waits for zero active processes before writing a cleanup receipt; disposal additionally waits for supervisor close.
- A host crash closes the job handle and kills members, but missing confirmation still rejects disposal. Failed cleanup stays latched, retaining process ownership and blocking reconnect. Concurrent connects/disposals and callbacks from old children are covered.
- Unsupported platforms reject before spawning. This deliberately avoids claiming equivalent containment from a Unix process group. PowerShell Add-Type must work on the target Windows installation; failure does not silently use weaker cleanup.
- Turns send the pinned protocol's `sandboxPolicy: { type: 'readOnly', networkAccess: false }`; threads retain their separate `sandbox: 'read-only'` field. Approval requests remain denied.
- Startup and thread overrides disable web search, apps, plugins, multi-agent features, and skill MCP dependency installation. Effective cwd configuration is checked before thread creation; enabled or unverifiable MCP server entries reject the session.

The pinned CLI merges an empty `mcp_servers={}` override with existing entries; it does not remove them. A local sentinel configuration probe demonstrated this. The implementation therefore rejects enabled entries instead of relying on an empty override or dedicated CODEX_HOME alone.

Read-only policy constrains writes; it is not filesystem read confinement and does not prohibit all command execution. U3 must supply the planned private empty working directory. Command sandbox network and built-in web search are explicitly disabled. U9 remains responsible for an authorized live-provider smoke test.
