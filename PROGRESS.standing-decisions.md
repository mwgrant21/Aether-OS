# Aether OS — Standing decisions

Binding architectural decisions, privacy/security rules, and standing gotchas extracted from `PROGRESS.md`'s shipped-plan history during the 2026-08-21 log-archivist compression pass. **This file is never compressed** — new binding items get appended here on future compression passes, older items are never removed. For full narrative context behind any item, see `PROGRESS.archive-2026-08-21.md`.

## Privacy & data model

- **Transcript content may be read/rendered but never stored (Stage 14, `docs/privacy-and-data.md` §4 amendment):** "transcript content may be read and rendered in a mounted view but must never enter the store, persistence, `~/.aether-os/`, or the collector schema; `src/state/noPayloadInStore.test.ts` is the mechanical enforcement."
- **Cross-engine Codex verification (Stage 17) is the one and only outbound-network exception to Stage 13.5's "no model call site" claim** — `docs/privacy-and-data.md` §9 amended accordingly. Default off, first enablement requires an explicit disclosure click-through, billing is structurally subscription-only (ChatGPT auth checked before every verification turn, not just at connect).
- **No model call site exists anywhere in this repo (Stage 13.5), enforced by `src/shared/noApiCalls.test.ts`.** Fuller detail is already binding in this repo's own `CLAUDE.md` under "Model calls" — do not reintroduce `@anthropic-ai/sdk`, a `chat:send`-style IPC pair, or any `messages.create(` call site without updating that guard test.
- **Known still-open gap, not yet fixed:** `~/.aether-os/` (including the collector's spool directory) lacks user-only Windows ACL hardening, despite `docs/privacy-and-data.md` §7 calling for it (flagged since Stage 2, 2026-07-27; cross-cutting fix, out of scope for any single stage so far).

## Architecture / standing conventions

- **`node:sqlite`'s `DatabaseSync` can only be imported as a type** (`import type { DatabaseSync } from 'node:sqlite'`) anywhere under `collector/` and in `electron/collectorStore.ts` — a static value import fails under Vite's dependency scanner (Stage 2 Task 3, reconfirmed Stage 3 Task 7).
- **The `Approval`/`ADD_APPROVAL`/`state.approvals` system and the real `PermissionRequest`/`PostToolUse` approval loop are orthogonal, not duplicate — keep `Approval` entirely, never remove it.** Investigated twice (Stage 6 Task 8, 2026-07-28, and re-confirmed at Stage 6's Task 8 review): `Approval` gates a simulated in-app Agent action or decorative risk event across 3 real, still-tested consumers (the reactor-simulation's random no-verb approvals, the chat action-JSON pipeline's risky-verb queue, Terminal's `approve`/`deny` commands). `PermissionRequestUI`/`PostToolFlagRequestUI` gate a real, live Claude Code tool call via a resolver Promise in `main.ts`. A decision-note comment lives above the `Approval` interface in `src/state/types.ts`.
- **Ledger pricing table, verified 2026-08-07 (`PRICING_VERIFIED_AT`), corrected two of three tiers that were wrong:** `opus` was carrying the retired Opus 3 rate (`15/75`, a 3x overstatement) — corrected to `5/25`; `haiku` was `0.8/4` (understated ~20%) — corrected to `1/5`; `sonnet`'s `3/15` was already correct. Sonnet 5 carries an introductory `2/10` rate through 2026-08-31 — Sonnet 5 ledger figures read ~50% high until that date passes, by design (the durable standard rate is what's stamped, not the promo rate).
- **Stale-dispatch-fatal detection does not survive a collector restart (Stage 11):** `staleDispatchSweep.ts`'s only input is an in-memory map rebuilt from scratch on collector startup, so a dispatch already hanging when the collector restarts silently never gets a `dispatches` row at all, rather than being retroactively marked fatal.
- **Pre-schema-v8 databases may be permanently missing nested subagent usage, and the gap cannot be closed safely (issue #40, Stage 15).** The two possible causes (a legacy Node collector that never ingested nested usage, vs. a usage-aware Go collector that already did) are not distinguishable from the database alone — every pre-v8 `usage_events` row has `source_file_rel` NULL regardless of which collector wrote it. Any future fix must be an explicit, opt-in, clearly-costed rebuild command (wipe `usage_events`, reset offsets, rescan) — never a silent migration. Only pre-v8 databases are affected; from v8 onward every usage event records `source_file_rel`, so the question is answerable going forward.

## Agent Memory Layer 2 (design doc, unbuilt as of this compression)

Full design context: `docs/superpowers/specs/AGENT_PERSONALITY_LAYER_1.md` (rev 3.1) and the archived PROGRESS.md entry. These decisions are binding for whoever eventually builds Layer 2:
- **Layer 2 must open its own `~/.aether-os/memory.db`, never `collector.db`.** `collector/`'s `retention.ts` deletes raw rows past 30 days and Settings exposes a real Purge — both correct for telemetry, catastrophic for a standing decision that must survive every sweep.
- **Invalidation is a hard `DELETE` plus a `memory_tombstones` row, never a soft `resolved` status** — a superseded judgment must not remain retrievable. This is the one point where the design deliberately diverges from its source-material precedent (Miriel), which marks a superseded fact `resolved` and leaves it retrievable forever.
- **`MemoryKind` is `decision | preference` (shared) plus `overrule | habit | revision` (private) — a `constraint` kind was considered and rejected**, with a test pinning the rejection. Its own canonical example ("no VS Build Tools on this box") was falsified a day after being written — the general lesson: a decision justified by an environmental constraint has no defence the day the constraint lifts.
- **Narration is a separate model call from the work call, and severity is computed by the runtime, never self-reported by the agent** — the first design draft was circular, since severity derives from terminal telemetry (`elapsed_ms`, `exit`) that doesn't exist while the agent is still producing output.
- **P4 principle — findings survive social pressure; only evidence moves them.** An agent may revise a stated finding only on new evidence or a named flaw in its own reasoning, never because the user disagreed or asked again, and must emit a structured `Revision{finding_id, cause, detail}` when it does.
- **`src/components/memory/`'s current `MemoryStub` decay/`strength`/`sweep` mechanism must be retired, not extended, once Layer 2 lands** — decay-based forgetting of standing decisions is the exact anti-pattern this design rejects (see the `freshness`/`overuse` rejection above).
